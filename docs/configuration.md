# Configuration reference

All AI Watchtower settings are environment variables prefixed with `WATCHTOWER_`. The full list is in [`.env.example`](../.env.example); this doc explains what each one does and how to choose values.

## Azure tenancy

| Variable | Required | Description |
|---|---|---|
| `WATCHTOWER_SUBSCRIPTION_ID` | yes | Azure subscription ID (GUID) that owns the Foundry / APIM / KV resources. |
| `WATCHTOWER_RESOURCE_GROUP` | yes | Name of the resource group containing Foundry, APIM, KV, Log Analytics. |
| `WATCHTOWER_LOCATION` | yes | Azure region short name (e.g. `eastus2`, `canadacentral`, `swedencentral`). Used for new Foundry project creation. |

The user-assigned MI must have Reader on the RG plus the role-specific grants listed in the [architecture doc](./architecture.md#authentication).

## Existing Azure resources

| Variable | Required | Description |
|---|---|---|
| `WATCHTOWER_FOUNDRY_ACCOUNT` | yes | Name of the Foundry (Cognitive Services / AIServices) account. |
| `WATCHTOWER_APIM_SERVICE` | yes | Name of the API Management service. Developer tier or higher; **APIM v2 required for `azure-openai-token-limit` policy**. |
| `WATCHTOWER_KEY_VAULT` | yes | Name of the Key Vault. Must be in RBAC authorization mode, not access policies. |
| `WATCHTOWER_CONTENT_SAFETY_ACCOUNT` | no | Name of a Content Safety account. If set, the APIM policy adds an `llm-content-safety` fragment. If blank, that fragment is skipped. |

## Authentication

| Variable | Required | Description |
|---|---|---|
| `WATCHTOWER_MANAGED_IDENTITY_CLIENT_ID` | prod: yes | Client ID of the user-assigned MI. Bicep sets this automatically at deploy time. **Leave blank for local dev**; `DefaultAzureCredential` will use your `az login` session. |
| `AZURE_CLIENT_ID` | prod: yes | Same value as above. `DefaultAzureCredential` looks at this env var to disambiguate when multiple identities are attached. Bicep sets it. |

For local dev the simplest path is `az login --tenant <your-tenant-id>` and don't set either variable. `DefaultAzureCredential` walks the credential chain and picks up your CLI session.

## Persistence

| Variable | Required | Description |
|---|---|---|
| `WATCHTOWER_DATABASE_URL` | prod: yes | Full async connection string, e.g. `postgresql+asyncpg://user:pass@fqdn:5432/db?ssl=require`. Bicep sets this to the Postgres Flex it provisions. When set, `WATCHTOWER_DB_PATH` is ignored. |
| `WATCHTOWER_DB_PATH` | no | SQLite file path. Only used when `WATCHTOWER_DATABASE_URL` is unset. Default: `/home/data/watchtower.db`. Fine for local dev; do not use in prod because App Service instances get recycled. |

## CORS

| Variable | Description |
|---|---|
| `WATCHTOWER_CORS_ORIGINS` | Comma-separated origin list. Default `*` (wide open). Set to your frontend URL in prod, e.g. `https://ai-watchtower.contoso.com`. |

The frontend is served from the same origin as the API in prod (Vite build baked into the backend Docker image), so CORS mostly matters for local dev when the Vite dev server runs on `:5173` and hits the FastAPI on `:8000`.

## Where these values come from

| Environment | How they get set |
|---|---|
| Local dev | `.env` file at repo root, loaded manually (`export $(cat .env \| xargs)` in bash; `Get-Content .env \| ForEach-Object { ... }` in PowerShell). |
| App Service (prod) | Application settings, populated by the Bicep in `infra/main.bicep` from Bicep parameters. |
| Docker | `--env-file .env` or `-e WATCHTOWER_...=...`. (No Dockerfile shipped in this release; see [issue tracker](https://github.com/) if you want one.) |

## Values NOT stored as env vars

- **APIM subscription keys** - generated by APIM at intake time, stored in Key Vault, referenced by URI in the DB. Never in env vars, never in logs, never in the UI.
- **Model pricing** - fetched live from Azure Retail Prices API, cached for 24h in-process. Fallback hardcoded table in `retail_prices.py`.
- **Foundry model catalog** - fetched live from Cognitive Services `models` endpoint at intake time.

## Deriving values from an existing environment

If you inherited an environment and don't know what to fill in:

```bash
# Find the Foundry account
az cognitiveservices account list -g <rg> --query "[?kind=='AIServices'].name" -o tsv

# Find the APIM service
az apim list -g <rg> --query "[].name" -o tsv

# Find the Key Vault (must be RBAC)
az keyvault list -g <rg> --query "[?properties.enableRbacAuthorization].name" -o tsv

# Find the Log Analytics workspace
az monitor log-analytics workspace list -g <rg> --query "[].name" -o tsv
```
